# Engineering Technical Interview

**Level: expert.** General catalog - hiring, internal promotion, or candidate preparation. Optional roles: Tech Lead / Code Reviewer. HR recruitment pipeline -> also `hr-technical-interview` (HR pack).

## When to use

- Design or run engineer technical interviews (live / take-home)
- Mock interviews and answer practice for candidates
- 1-5 scoring rubric per technical dimension
- Take-home brief + review summary before `code-review`
- Keywords: technical interview, live coding, system design, mock interview, technical test

## When not to use

- HR behavioral / psychometric test -> HR pack (`hr-cv-lifecycle`, `hr-psychometric`)
- SIMRS / hospital domain -> `simrs-technical-assessment`
- Production PR review without assessment context -> `code-review`
- Automatic hire verdict

## Procedure

### 1. Context

- Track: backend / frontend / fullstack / mobile / QA automation / DevOps
- Level: junior / mid / senior / lead
- Stack (if any)
- Format: live 60-90 min / take-home / score submission
- Mode: interviewer | candidate prep | score work

Default: mid backend, live 90 min, interviewer mode.

### 2. Session structure (live)

| Block | Time | Content |
|------|-------|-----|
| Warm-up | 10 min | Experience & stack |
| Deep-dive | 25 min | API, UI, data, infra per track |
| Coding / debug | 25 min | Small function or snippet fix |
| Trade-offs | 15 min | Scale, reliability, security |
| Q&A | 10 min | |

### 3. Tracks & rubrics

Dimension details, sample questions, take-home: `reference.md`.

Example pass (mid): average dimension >=3.5, no required dimension <2.

### 4. Take-home

Brief: limited scope, README, minimal tests, no over-engineering.

Submission review: hiring-relevant summary -> handoff to `code-review` for diff details.

### 5. Handoff

| Context | Skill |
|---------|--------|
| Recruitment + HR ethics | `hr-technical-interview` |
| SIMRS / hospital | `simrs-technical-assessment` |
| Submission code review | `code-review` |
| Deep backend/frontend domain | `backend-engineering`, `frontend-engineering`, `api-engineering` |
